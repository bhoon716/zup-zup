# 의사결정 기록

프로젝트에 영향을 주는 제품, 도메인, API·데이터, 보안, 의존성, 인프라, 배포, 운영 결정은 이 디렉터리에 Markdown으로 기록한다. 결정 전의 가정과 미확인 사항도 구분해서 남긴다.

## 작성 방법

- 새 기록은 [`TEMPLATE.md`](TEMPLATE.md)를 복사해 시작한다.
- 파일명은 `YYYY-MM-DD-짧은-주제.md` 형식으로 쓴다.
- 결정 상태는 `Proposed`, `Accepted`, `Rejected`, `Superseded`, `Withdrawn` 중 하나로 표시한다.
- 한 기록에는 하나의 결정 질문을 담고, 관련된 대안·근거·결과·검증 조건을 적는다. 간단한 결정은 템플릿을 짧게 작성하고, 영향이 크거나 되돌리기 어려운 결정은 충분한 대안 비교와 전환·복구 계획을 남긴다.
- 기존 기록의 결정을 바꾸면 과거 내용을 고쳐 쓰지 말고 새 기록을 만들고 `Supersedes`로 연결한다.
- 새 기록은 [저장소 문서 인덱스](../../.agents/docs/index.md)의 Decisions 목록에도 연결한다.

기존 네 결정 문서는 이력을 보존하기 위해 현재 위치와 내용을 유지한다. 과거 문서는 각 결정 당시의 사실과 상태를 기록하며, 현행 운영 상태는 코드·설정·운영 증거로 별도 확인한다.
