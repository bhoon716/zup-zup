# 결정: 프로젝트 의사결정 기록 위치와 규칙

- 상태: Accepted
- 결정일: 2026-09-29
- 범위: 제품, 도메인, API·데이터, 보안, 의존성, 인프라, 배포, 운영 결정 기록
- 대체 결정: 없음
- 관련 자료: [기록 안내](README.md), [결정 템플릿](TEMPLATE.md), [저장소 문서 인덱스](../../.agents/docs/index.md)

## 배경과 결정 질문

프로젝트 의사결정은 기존 `docs/decisions/`에 네 개의 Markdown 기록으로 보관되어 있다. 별도 `.agents/decisions/`를 만들면 같은 종류의 문서가 두 위치로 나뉘고 기존 링크도 이동해야 한다. 앞으로 기록을 어느 위치에 모을지 정할 필요가 있다.

## 선택지

| 선택지 | 얻는 점 | 비용·위험 |
| --- | --- | --- |
| 기존 `docs/decisions/` 사용 | 과거 기록과 링크를 유지하고 하나의 기준 위치를 제공한다. | 에이전트 안내와 인덱스에 위치를 명시해야 한다. |
| 새 `.agents/decisions/` 생성 | 에이전트 전용 자료라는 점이 경로에서 드러난다. | 기록이 분산되고 기존 문서·링크를 옮기거나 중복 관리해야 한다. |

## 결정

모든 프로젝트 의사결정 Markdown은 기존 `docs/decisions/`에 기록한다. 새 결정은 `TEMPLATE.md`를 사용하고 파일명은 `YYYY-MM-DD-짧은-주제.md` 형식으로 한다. 새 기록을 `.agents/docs/index.md`의 Decisions 목록에도 연결한다. 기존 기록은 역사 보존을 위해 이동하거나 내용을 덮어쓰지 않는다.

## 근거와 가정

- 근거: 기존 결정 파일 네 개가 `docs/decisions/`에 있으며 저장소 인덱스와 README에서 이 경로를 참조한다.
- 가정 또는 미확인: 없음.
- 결정을 바꿀 수 있는 증거: 프로젝트 문서 구조 자체가 변경되어 별도 결정 기록 저장소가 필요한 경우.

## 결과와 위험

- 기대 효과: 새 기록과 기존 결정 이력이 한 위치에 모이고, 작성 양식과 링크 경로가 일관된다.
- 감수하는 비용·제약: 새 결정마다 파일과 인덱스 링크를 추가해야 한다.
- 대응할 위험: 기록이 오래되거나 상충하면 이전 문서를 고쳐 쓰지 않고 새 결정으로 대체 관계를 명시한다.

## 검증과 재검토 조건

저장소 지침과 문서 인덱스가 `docs/decisions/` 및 템플릿을 가리키는지 확인한다. 저장소 구조 또는 의사결정 기록 정책이 바뀌면 재검토한다.
