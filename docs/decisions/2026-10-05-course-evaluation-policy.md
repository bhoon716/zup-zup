# 결정: 별점·이모지는 과목코드와 교수 기준으로 묶어 집계한다

- 상태: Accepted
- 결정일: 2026-10-05
- 범위: 강의 별점·이모지의 평가 집계 단위
- 대체 결정: 없음
- 관련 자료: [ReviewScopeKey](../../apps/server/src/main/java/bhoon/sugang_helper/academic/review/domain/ReviewScopeKey.java), [CourseReviewService](../../apps/server/src/main/java/bhoon/sugang_helper/academic/review/application/CourseReviewService.java), [CourseEmojiReviewService](../../apps/server/src/main/java/bhoon/sugang_helper/academic/review/application/CourseEmojiReviewService.java), [탈퇴 후 평가 보존 정책](2026-10-04-authentication-policy.md)

## 문제와 목표

이전 수강자의 평가를 새 학기의 강의 선택에 활용할 수 있도록 별점·이모지를 어떤 강의끼리 묶을지 정한다. 제품에 있는 별점과 이모지를 대상으로 하며, 글 리뷰 기능을 새로 추가하는 결정은 아니다.

## 확인된 사실과 미해결 사항

- 현재 코드는 교수명이 있으면 과목코드와 교수명으로 관련 강의를 찾아 별점·이모지를 집계한다. 해당 조회 조건에는 학기·분반 제한이 없다.
- 교수명이 비어 있거나 ‘교수 미지정’이면 현재 코드는 해당 강의의 `courseKey`를 기준으로 처리한다. 이 현재 동작을 모든 예외에 대한 확정 정책으로 확대하지 않는다.
- 사용자는 교수명이 ‘외부교원1’처럼 표시되는 경우도 있다고 추가로 설명했다. 이런 문자열이 같은 실제 교수를 뜻하는지는 확인되지 않았다.
- 교수 미지정·임시 표시의 처리, 동명이인·교수명 변경·공동 담당 교수의 식별 방식은 후속 논의 또는 상세 설계에서 정한다.

## 선택지 비교

| 방식 | 동작 | 장점·제약 |
| --- | --- | --- |
| 과목코드 + 교수 기준 | 같은 과목·교수의 평가를 학기·분반을 넘어 합산 | 이전 평가를 활용할 수 있으나 학기별 수업 변화가 섞일 수 있음 |
| 학기·분반별 분리 | 개설된 강의별로 평가를 별도 집계 | 해당 수업의 평가를 구분할 수 있으나 새 학기에는 평가가 부족해짐 |

## 결정

1. 별점·이모지는 같은 과목코드와 같은 교수의 강의를 하나의 평가 그룹으로 묶어 집계한다. 같은 그룹은 학기·분반이 달라도 이전 평가를 함께 활용한다.
2. 과목코드가 다르거나 교수가 다른 강의는 같은 그룹으로 합치지 않는다. 과목명이 비슷하다는 이유만으로 합치는 방식으로 확대하지 않는다.
3. ‘외부교원1’처럼 실제 교수를 구별할 수 있는지 불명확한 표시는 별도 예외 처리를 논의한다. 이번 기본 기준 선택만으로 그런 표시의 단순 문자열 일치를 동일 교수 판정으로 승인하지 않는다.
4. 탈퇴한 사용자의 별점·이모지도 보존하고 공개 집계를 유지하는 기존 정책을 적용한다. 계정당 평가 수, 수정·취소 규칙과 집계 갱신 구조는 후속 논의에서 정한다.

## 근거와 결과

- 이전 수강자의 평가를 강의 선택에 활용하는 목적에 맞춰 과목코드·교수 기준의 1번을 제안했고, 사용자가 선택했다.
- 학기마다 평가를 새로 쌓는 부담을 줄이는 대신, 학기별 강의 구성 변화가 집계에 섞일 수 있다는 제약을 수용한다.
- 사용자가 추가로 제시한 임시 교수명 사례는 서로 다른 담당자의 평가가 잘못 합쳐질 위험과 관련되므로 별도 예외 정책을 논의한다.

## 기록과 구현 상태

- 사용자의 선택을 저장 여부를 별도로 묻지 않고 기록하고 결정 목록에 추가했다.
- 애플리케이션 코드·실행 설정은 변경하지 않았으며 테스트를 추가하거나 실행하지 않았다.

## 추가 결정: 임시 교수명도 현재 집계 방식을 유지하고 필요 시 재검토한다

- 상태: Accepted
- 결정일: 2026-10-05
- 범위: ‘외부교원1’ 등 임시 교수명과 교수명 누락 시 집계 기준
- 대체 범위: 앞선 기본 결정에서 미정으로 남긴 임시 교수명 예외 처리의 초기 정책

### 확인과 결정

1. 별점·이모지 집계의 교수명 처리는 우선 현재 방식대로 유지한다. 앞뒤 공백을 제거한 교수명 문자열과 과목코드를 기준으로 학기·분반을 넘어 묶는다.
2. ‘외부교원1’ 같은 값도 별도의 임시 이름 판별·교수 연결 정보를 도입하지 않고 일반 교수명 문자열과 동일하게 처리한다. 같은 과목코드와 같은 표시 이름이면 평가를 합산한다.
3. 교수명 값이 `null`·빈 값·공백뿐이거나 ‘교수 미지정’이면 현재처럼 해당 개설 강의의 `courseKey`별로 처리한다.
4. 표시 이름이 같아도 실제 담당자가 다를 수 있다는 제약을 수용한다. 동일한 이름을 사용한다는 사실만으로 실제 동일 인물임을 보장하지 않는다.
5. 사용자가 필요성을 느끼거나 서로 다른 담당자의 평가가 섞이는 사례 등이 확인되면, 임시 이름 분리·실제 교수 식별 방식의 도입 여부를 재검토한다. 구체적인 신규 식별 구조는 이번에 확정하지 않는다.

### 근거와 기록 상태

- 사용자는 ‘외부교원1’ 사례를 제시한 뒤 현재 코드의 동작을 확인하고, 우선 현재 방식을 유지하며 나중에 필요하다고 느끼면 재검토하겠다고 선택했다.
- 앞선 문서의 미정 기록은 보존하고 이번 초기 정책을 문서 끝에 추가했다. 이 결정은 계정당 평가 수·수정 규칙을 추가로 확정하는 선택은 아니다.
- 애플리케이션 코드·실행 설정은 변경하지 않았으며 테스트를 추가하거나 실행하지 않았다.

## 추가 결정: 강의 교수명은 null·빈 문자열로 저장하지 못하도록 한다

- 상태: Accepted
- 결정일: 2026-10-05
- 범위: 재설계에서 강의 교수명 필드의 저장 규칙
- 관련 자료: [Course](../../apps/server/src/main/java/bhoon/sugang_helper/academic/course/domain/Course.java), [CourseCatalogSynchronizationService](../../apps/server/src/main/java/bhoon/sugang_helper/academic/course/application/CourseCatalogSynchronizationService.java), [강의 수집 정책](2026-10-04-course-collection-policy.md)

### 확인과 결정

1. 강의 교수명은 `null`·빈 문자열·공백만 있는 값으로 저장하지 못하도록 한다. 앞뒤 공백을 정리한 뒤 비어 있지 않은 값을 갖도록 하는 저장 규칙을 재설계에 적용한다.
2. ‘외부교원1’처럼 값이 있는 표시 이름은 앞서 선택한 현재 집계 기준을 유지한다. 이번 제약만으로 실제 교수 식별·연결 기능을 추가하지 않는다.
3. 학교 데이터에 교수명이 없을 때 대체 표시를 저장할지 해당 항목의 저장을 거부할지는 이어서 논의한다. null·빈 문자열을 허용하지 않는다는 요구만으로 한 방식을 임의로 확정하지 않는다.
4. 기존 누락 데이터의 정리, 저장 경로별 검증과 DB 제약의 구성·적용 순서는 상세 설계에서 정한다. 앞선 null·빈 값의 집계 처리 설명은 기존 코드 동작의 기록이며, 신규 저장에서 해당 값을 계속 허용한다는 정책으로 적용하지 않는다.

### 근거와 기록 상태

- 사용자는 현재 집계 방식을 유지하겠다는 선택에 이어 교수명에 null·빈 문자열이 들어오지 못하도록 요청했다. 공백만 있는 값도 동일한 누락 값으로 취급하도록 기록했다.
- 현재 수집 코드의 `canonical`은 빈 문자열을 null로 바꾸고, 강의 엔티티 교수명에는 `nullable = false`가 설정되어 있지 않다. 이번 요구는 현재 코드에서 이미 보장되는 제약이 아니다.
- 사용자의 요구를 저장 여부를 별도로 묻지 않고 기록했다. 애플리케이션 코드·실행 설정은 변경하지 않았으며 테스트를 추가하거나 실행하지 않았다.

2. DB에 저장되는 강의 교수명에는 null·빈 문자열을 허용하지 않는 앞선 규칙을 적용한다. 교수명이 누락됐다는 상태는 값이 비어 있는 대신 ‘교수 미지정’이라는 명시적인 표시로 표현한다.
3. ‘교수 미지정’인 강의의 별점·이모지는 현재처럼 해당 개설 강의의 `courseKey`별로 집계한다. 같은 과목코드와 같은 미지정 표시라는 이유로 서로 다른 개설 강의의 평가를 합치지 않는다.
4. ‘외부교원1’ 등 비어 있지 않은 표시 이름은 앞서 선택한 과목코드·교수명 기준을 유지한다. 이번 대체 표시 규칙을 임시 교수명 분리 정책으로 확대하지 않는다.
5. 기존 누락 값 정리와 저장 경로별 정규화·검증, DB 제약 적용은 상세 설계에서 정리한다. 이번에는 정책을 기록하며 실제 데이터 이관·코드 변경은 수행하지 않는다.

### 근거와 기록 상태

- 강의·여석 정보 갱신을 유지하고 교수명 누락을 명시적인 값으로 표현할 수 있도록 대체 표시를 사용하는 1번을 제안했고, 사용자가 선택했다.

| 방식 | 동작 | 장점·제약 |
| --- | --- | --- |
| 별점 하나·수정 허용 | 같은 그룹에서 기존 별점을 수정 | 계정당 하나의 의견을 반영하고 규칙이 단순하지만 과거 점수는 현재 집계에서 대체됨 |
| 학기마다 별점 추가 | 같은 계정의 과거·현재 별점을 함께 집계 | 학기별 경험을 남길 수 있지만 같은 계정이 집계에 여러 번 반영됨 |

1. 같은 평가 그룹에는 계정당 별점 하나만 두고 본인의 기존 별점을 수정할 수 있도록 한다. 학기·분반이 바뀌었다는 이유만으로 같은 그룹에 별점을 추가하지 않는다.
2. 별점 수정 시 기존 점수는 현재 집계에서 제외하고 수정된 점수 하나를 반영한다. 예를 들어 3점에서 4점으로 수정하면 4점 하나만 반영하고 평가 참여 수는 증가시키지 않는다.

4. 여기서 제한하는 단위는 계정이다. 탈퇴 후 새 계정으로 재가입하는 사용자를 동일 인물로 식별해 중복을 막는 신규 구조로 확대하지 않으며, 탈퇴한 계정의 평가 보존·공개 집계 유지 정책도 적용한다.
5. 현재 서비스의 그룹 내 중복 작성 검사와 별점 수정 기능을 확인했다. 동시 요청에서도 제한을 보장하는 저장 구조, 기존 중복 데이터 처리, 수정 이력 보존과 별점 취소·삭제 규칙은 상세 설계 또는 후속 논의에서 정한다.

### 근거와 기록 상태
