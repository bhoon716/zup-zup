# 공개 강의 정보의 Clarity 마스킹 예외

## 승인과 범위

2026-10-28 사용자는 공개 과목 정보에 한해 Clarity 마스킹을 풀고 입력값·개인 시간표·개인정보를 계속 보호하는 변경과 배포를 승인했다. 기존 body `data-clarity-mask="true"`는 유지한다. 전역 Relaxed 변경, 계정·토큰 생성, 과거 녹화 복원은 이번 작업에 포함하지 않는다.

공개 검색과 공개 강좌 상세에서 공개 상태가 정확히 `공개`인 강의의 강의명·학점/강의시간 텍스트만 `data-clarity-unmask="true"`로 표시한다. 공개 여부가 없거나 비공개이면 보호를 유지한다. 교수·장소·평점·리뷰·사용자 이름·입력·개인 액션은 이번 예외에 넣지 않는다.

공유 Table/Detail/Dialog는 기본값이 보호이며, 공개 화면만 명시적으로 허용한다. 시간표·구독의 상세 popup에는 허용 flag를 전달하지 않는다. 공개 검색 안에서도 찜한 강의 필터 또는 선택 공강 조건이 있으면 개인 맥락으로 보고 예외를 끈다. 입력을 복사한 검색 제목·filter chip도 body 보호를 상속한다. 리뷰나 입력을 함께 감싸는 넓은 비마스킹 wrapper는 만들지 않는다.

## 근거와 대안

[Microsoft 공식 문서](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-masking)는 HTML mask/unmask attribute와 중첩된 예외를 설명하며 input/dropdown은 모든 mode에서 보호한다고 명시한다. root mask 제거는 개인 화면·재사용 컴포넌트·리뷰의 범위가 너무 넓고, console selector만 변경하면 코드와 실제 배포의 검증이 분리된다. 공개 맥락의 명시적 flag와 텍스트 leaf 예외를 택한다.

## 검증과 한계

단위 테스트로 공개/비공개/미지정, 개인 기본값, 개인 검색 조건과 초기화, 리뷰·입력·개인 액션의 보호 경계를 확인한다. 로컬 E2E는 외부 요청을 차단하고 실제 DOM의 제한된 예외 및 private popup을 확인한다. 이는 Clarity 전송 payload나 재생 결과를 직접 검증한 것과 구분한다.

배포 후 공개 경로와 개인 경로의 DOM을 읽기로 검수하고, 가능한 경우 새 녹화에서 적용을 확인한다. 과거 녹화에는 소급 적용되지 않으며 Microsoft 안내에 따라 반영에는 시간이 걸릴 수 있다. 실제 새 녹화를 확인하지 못하면 미검증으로 보고한다. 새 개인정보를 녹화하려고 입력하거나 기존 사용자 데이터를 변경하지 않는다.

## 별도 발견: 공개 상세 URL 인코딩

로컬 E2E에서 `/courses/2026%3A...`처럼 이미 인코딩한 courseKey를 넣으면 기존 useParams 값이 API에서 다시 encode되어 `%253A` 요청이 나오는 것을 trace로 확인했다. 해당 파싱·API 호출 코드는 기준 `6c1142ed`에도 동일하다. 현재 범위는 Clarity 예외이므로 이 기존 경로 문제를 수정하지 않으며, 실패 trace는 작업 산출물에 보존한다. 공개 상세의 마스킹 E2E는 실제 동작하는 콜론 원문 경로를 사용한다. 보호 assertion은 제거하거나 약화하지 않는다. 운영에서 인코딩한 URL의 서버 처리 결과와 별도 수정은 후속 검토 사항이다.

후속 확인에서 콜론 원문 URL도 client params에서 인코딩되어 같은 요청 실패를 재현했다. 앞의 원문 경로 동작 가정은 정정한다. 공개 상세 화면 검증의 선행 조건을 복구하기 위해 해당 페이지에서 route key를 한 번 decode한 후 기존 API의 encode를 유지한다. malformed percent는 원래 문자열로 조회 실패 안내를 유지하며 인증/조회 권한/서버 API는 변경하지 않는다. raw·encoded·malformed 단위 테스트와 실제 공개 상세 E2E로 범위를 제한한다. 이 복구는 공개 정보 허용 항목을 늘리지 않는다.

## 최종 로컬 검증

현재 결론은 제한된 공개 텍스트 예외와 공개 상세 route key의 1회 복원이다. body mask·개인 기본값·공개 여부 미지정의 보호는 유지한다.

- Node 22.23.4에서 전체 336개 단위 테스트, lint, TypeScript, production build 통과.
- 12개 Playwright E2E가 재시도 0회로 통과. 원문/인코딩 공개 상세 URL, 공개 popup, 검색어·찜 조건, 개인 구독·시간표 popup을 포함한다. 외부 요청을 차단하고 가짜 API만 사용했다.
- 최초 Node 25 실행의 기존 emoji picker timeout은 테스트를 수정하지 않고 지정 런타임의 전체 검사로 재확인했다. 개인 필터의 draft/apply 차이와 기존 key 인코딩 실패 증거는 별도 보존했다. skip·assert 완화는 하지 않았다.
- 공유 Mac 브라우저와 NPM 탭·터널은 사용하지 않았다. 실제 새 녹화 재생 검증과 운영 DOM 확인은 배포 후 별도 단계다.
