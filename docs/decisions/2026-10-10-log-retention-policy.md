# 결정: 최근 로그는 바로 조회하고 과거 로그는 압축하여 보관한다

- 상태: Accepted
- 결정일: 2026-10-10
- 범위: 일반 서버 로그의 조회와 장기 보관 방식
- 대체 결정: 없음. 일반 로그의 기간 후 삭제는 비교한 제안이며 채택된 결정이 아니었음
- 관련 자료: [관리자 작업 기록과 계정 정책](2026-10-04-authentication-policy.md), [DB·첨부 파일 백업 정책](2026-10-10-database-backup-policy.md)

## 문제와 목표

최근 로그를 쉽게 확인하면서 오래된 로그도 문제 조사에 사용할 수 있도록 남긴다. 일반 로그를 일정 기간 뒤 삭제하는 제안에 대해 사용자가 과거 로그의 처리 방식을 질문했고, 최근 로그와 과거 압축 파일을 나누어 보관하는 방식을 선택했다.

## 선택지 비교

| 선택지 | 장점 | 비용·제약 |
| --- | --- | --- |
| 보관 기간이 지난 로그 삭제 | 저장량을 제한하기 쉬움 | 삭제된 과거 로그로 조사할 수 없음 |
| 최근 로그는 바로 조회하고 과거 로그는 압축 보관 | 최근 조회를 유지하면서 과거 로그도 남길 수 있음 | 과거 로그 조사 시 압축 파일을 찾아 풀어야 하며 총저장량은 계속 증가함 |
| 전체 로그를 계속 조회 가능하게 영구 보관 | 오래된 로그도 계속 조회 가능 | 조회 대상과 저장량이 누적되어 관리 부담이 증가함 |

## 결정

1. 최근 일반 서버 로그는 바로 조회할 수 있게 유지한다.
2. 최근 조회 기간을 지난 로그는 삭제하지 않고 압축 파일로 장기·영구 보관한다. 과거 로그를 조사할 때 해당 파일을 찾아 압축을 풀어 확인하는 방식을 수용한다.
3. 바로 조회할 최근 기간은 아직 확정하지 않았다. 앞서 제안한 30일을 사용자의 이번 선택만으로 확정하지 않는다.
4. 압축 보관 로그에는 DB·문의 첨부 백업의 최신 세 개 보관 제한을 적용하지 않는다. 백업 정책을 이유로 오래된 압축 로그를 자동 삭제하지 않는다.
5. 기존 관리자 작업·탈퇴 처리 기록의 영구 보존 결정을 유지한다. 관리자 작업 기록을 서버 로그로만 남기는 기존 방향도 유지하며, 탈퇴 처리 기록의 저장 방식을 이번 결정으로 변경하지 않는다.
6. 이번 선택으로 전체 과거 로그의 상시 검색 기능이나 새로운 로그 수집·검색 서비스를 도입하지 않는다. 구체적인 조회·압축 도구는 상세 설계에서 정한다.

## 근거와 결과

사용자는 최근 로그만 바로 조회하고 과거 로그는 압축 보관하는 방식을 명시적으로 선택했다. 오래된 문제를 조사할 기록을 남기면서 전체 로그를 상시 조회 대상으로 유지하는 부담을 줄인다.

압축은 저장량을 줄이는 수단이며 영구 보관에 따른 누적 자체를 없애지는 않는다. 파일 보관만으로 디스크·서버 손실 시 복구까지 보장하지 않는다.

## 구현과 후속 논의

최근 조회 기간, 압축 주기·형식, 보관 위치와 서버 밖 사본 여부, 저장 공간 부족 대응 및 과거 파일의 조회 절차는 후속 논의 또는 상세 설계에서 정한다. 구체적인 보관 방법이 정해지기 전 영구 보존이 이미 구현되었다고 간주하지 않는다.

이번 변경은 의사결정 문서 작성이며 실제 로그 압축·삭제·이동, 서버 설정 변경이나 테스트 실행은 하지 않았다.

## 재검토 조건

압축 로그의 저장량이나 과거 로그 조사 빈도가 운영 부담으로 나타나면 보관 위치와 조회 방식을 재검토한다.

## 추가 결정: 바로 조회할 로그는 최근 30일로 한다

- 상태: Accepted
- 결정일: 2026-10-10
- 범위: 일반 서버 로그의 최근 조회 기간

### 비교와 결정

최근 30일·7일·90일을 바로 조회하는 방식을 비교한 뒤 사용자는 30일인 첫 번째 방식을 선택했다. 앞서 미정으로 남긴 최근 조회 기간을 확정한다.

1. 최근 30일의 일반 서버 로그는 바로 조회할 수 있게 유지한다.
2. 그 이전 로그는 기존 결정대로 압축 파일로 영구 보관한다. 30일이 지났다는 이유로 로그 기록 자체를 삭제하지 않는다.
3. 관리자 작업·탈퇴 처리 기록의 기존 영구 보존 결정은 유지한다.

### 근거와 후속 논의

최근 한 달의 문제를 바로 조사할 수 있도록 하면서, 전체 과거 로그를 상시 조회 대상으로 유지하는 부담을 제한한다. 7일보다 조회 대상 저장량이 많아지는 비용을 수용한다.

압축 파일의 보관 위치·서버 밖 사본 여부, 압축 주기·형식과 구체적인 조회 수단은 아직 확정하지 않았다. 이번 변경은 의사결정 기록이며 실제 로그 압축·삭제·이동이나 서버 설정 변경은 하지 않았다.

## 추가 결정: 압축 로그는 서버에 보관하고 외부 사본은 수동 복사한다

- 상태: Accepted
- 결정일: 2026-10-11
- 범위: 압축 로그의 보관 위치와 서버 밖 사본 확보 방식

### 비교와 결정

서버 보관과 외부 수동 복사, 서버 보관과 외부 자동 복사, 서버에만 보관하는 방식을 비교했다. 사용자는 첫 번째 방식을 선택했다.

1. 과거 로그의 압축 파일은 서버에 보관한다.
2. 서버 밖 사본은 필요할 때 운영자가 본인 PC 등으로 직접 복사하거나 다운로드한다. 외부 자동 복사 기능은 이번 재설계에 추가하지 않는다.
3. 최근 30일 바로 조회·이전 로그 압축 영구 보관 정책을 유지한다. 외부 사본을 만들었다는 이유만으로 서버 원본을 자동 삭제하는 정책은 이번 선택에 포함하지 않는다.
4. 서버와 디스크를 함께 잃으면 실제로 외부에 복사한 로그만 확보할 수 있다. 수동 복사를 하지 않은 로그까지 서버 밖에 보존된 것으로 간주하지 않는다.

### 근거와 후속 논의

DB·첨부 파일 백업과 같은 서버 보관·외부 수동 복사 방식을 사용하여 별도 자동 전송 구성을 관리하는 부담을 줄인다. 사본 복사 누락과 외부 사본의 최신성을 운영자가 관리하는 비용을 수용한다.

복사 시점·보관 경로, 압축 방식·조회 수단 및 서버 저장 공간 부족 대응은 후속 논의 또는 상세 설계에서 정한다. 로그의 영구 보관에는 DB 백업의 최신 세 개 제한을 적용하지 않는다.

이번 변경은 의사결정 기록이며 실제 로그 압축·복사·삭제·전송이나 서버 설정 변경은 하지 않았다.

## 추가 결정: 디스크 사용량이 기준을 넘으면 Discord로 안내한다

- 상태: Accepted
- 결정일: 2026-10-11
- 범위: 서버 저장 공간 부족에 대비한 운영자 안내
- 관련 결정: [장애 안내 정책](2026-10-10-health-check-policy.md)

### 비교와 결정

디스크 사용량이 기준을 넘으면 기존 장애 안내용 Discord 채널로 알리는 방식과 Grafana에서만 확인하는 방식을 비교했다. 사용자는 첫 번째 방식을 선택했다.

1. 서버 디스크 사용량을 확인하고, 정한 기준을 넘으면 기존 장애 안내용 Discord 채널로 운영자에게 안내한다. 저장 공간 부족을 파악하기 위해 운영자가 대시보드만 직접 확인해야 하는 방식은 채택하지 않는다.
2. 안내를 받은 운영자가 로그 이동이나 저장 공간 증설 등의 대응을 직접 판단한다. 이번 선택은 오래된 로그의 자동 삭제나 외부 자동 이동을 승인하는 결정이 아니다.
3. 최근 30일 바로 조회·이전 로그 압축 영구 보관과 서버 보관·외부 수동 복사 정책을 유지한다.
4. 구체적인 사용량 기준, 확인 주기, 안내 대상 디스크와 전송 구현은 상세 설계에서 정한다. 반복 안내와 복구 안내의 적용은 기존 장애 안내 정책과 함께 상세 설계에서 정리한다.

### 근거와 후속 논의

압축 로그를 계속 보관하면 저장량이 누적되므로, 대시보드를 직접 확인하지 않아도 공간 부족에 대응할 수 있도록 한다. 이번 결정만으로 실제 감시나 용량 확보가 완료되었다고 간주하지 않는다.

이번 변경은 의사결정 기록이며 실제 디스크 감시 설정·Discord 발송·파일 이동·삭제·저장 공간 증설은 하지 않았다.
