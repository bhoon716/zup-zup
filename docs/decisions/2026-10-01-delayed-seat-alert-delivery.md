# 결정: 지연됐다는 이유만으로 미발송 여석 알림을 취소하지 않는다

- 상태: Accepted
- 결정일: 2026-10-01
- 범위: 지연된 여석 알림의 발송 대상 유지와 미전달 작업 보존
- 대체 결정: 없음. 기존 발생 사실 발송·at-least-once 전달 목표를 보완한다.
- 관련 자료: [발생 사실 발송 결정](2026-10-01-seat-alert-occurrence-notification.md), [중복 허용·감지 시각 표시 결정](2026-10-01-notification-duplicate-and-mq-policy.md), [전달 목표와 완료 기준](2026-10-01-notification-at-least-once-delivery.md), [재설계 논의 계획](../backend-redesign-plan.md)

## 문제와 목표

외부 알림 서비스 장애 등으로 발송이 지연됐을 때, 오래된 발생 사실이라는 이유로 작업을 취소할지 늦게라도 전달할지 정한다. 미전달 작업의 만료·삭제가 사용자에게 필요한 발생 사실을 없애지 않도록 한다.

## 사용자 설명과 기존 요구

- 사용자는 정정기간이 잠시가 아니라 며칠 동안 이어진다고 설명했다.
- 사용자는 늦더라도 일단 알림을 받아보는 것이 중요하다고 판단했다.
- 여석이 발생했던 사실 자체를 전달하고 발송 전 현재 여석을 재조회하지 않는 방향은 기존 결정이다.
- 중복 허용, 최초 감지 시각 표시, 수집·전달 지연으로 실제 상태와 다를 수 있다는 안내도 기존 결정이다.

## 선택지 비교

| 논의한 선택 | 효과 | 비용·제약 |
| --- | --- | --- |
| 지연된 발생 사실도 전달 대상으로 유지 | 늦더라도 사용자에게 발생 사실을 전달할 기회를 보존 | 오래 대기한 작업의 저장·복구·처리 부담이 남음 |
| 지연을 이유로 미발송 작업을 취소 | 오래된 작업의 처리 부담 감소 | 사용자가 중요하게 여기는 발생 사실을 전달하지 못할 수 있음 |

## 결정

1. 일시적 장애 등으로 지연된 여석 알림도 발송 대상으로 유지한다.
2. 지연 시간이 길어졌다는 이유만으로 미발송 알림을 취소하거나 만료시키지 않는다.
3. 미전달 작업을 단순히 보관 기간이 지났다는 이유로 자동 삭제해 전달 기회를 없애지 않는다.
4. 늦게 발송하더라도 최초 여석 감지 시각을 그대로 표시한다. 발송 시각을 새 감지 시각처럼 표현하지 않는다.
5. 실제 여석 상태와 다를 수 있다는 안내를 유지하고, 과거 발생 사실을 전달한다.

## 근거와 결과

정정기간이 여러 날 이어지고 늦게라도 발생 사실을 받는 것이 중요하다는 사용자 요구가 근거다. 현재성이 낮아졌다는 이유만으로 전달할 가치를 없다고 판단하지 않는다.

오래된 미전달 작업을 보존하고 복구할 수 있는 설계가 필요하다. 완료된 알림 이력의 보존 기간은 별도로 정한다. 재시도 횟수·간격과 자동 재시도 지속 또는 관리자 재개의 선택은 이 결정에서 확정하지 않았다.

사용자 취소·채널 비활성화·잘못된 주소·해지된 기기 등은 지연과 다른 사유이므로, 해당 경우의 발송 대상 유지·취소·복구 정책은 후속 논의에서 정한다.

## 구현과 검증 상태

사용자가 지연된 알림의 전달 가치를 설명하고 이 기록의 작성을 승인했다. 애플리케이션 코드와 실행 설정은 변경하지 않았다.

현행 [실패 기록 정리](../../apps/server/src/main/java/bhoon/sugang_helper/seatalert/notification/application/NotificationDeliveryRetentionScheduler.java)는 기본 30일 후 DLQ 작업을 삭제한다. 미전달 작업의 복구 가능성이 보관 기간 때문에 사라지지 않도록 이 정책과 데이터 정리 범위를 구현 설계에서 재검토한다.

구현 시 오래 대기한 미발송 작업이 지연만을 이유로 취소되지 않는 동작과 최초 감지 시각 보존을 단위 테스트 후보로 둔다. 최종 E2E 범위와 실행 여부는 구현 논의에서 정한다. 이번 문서 작성에서는 테스트를 추가하거나 실행하지 않았다.

## 미결 사항과 재검토 조건

- 재시도 횟수·간격, 자동 재시도 지속 또는 중단 후 관리자 재개
- 장기 장애에서 쌓인 작업의 처리 순서·처리량과 운영 확인 방식
- 전달 불가·설정 오류·사용자 취소의 구분과 복구·정리 정책
- 완료 이력과 미전달 작업의 데이터 보존·정리 범위
- 오래된 알림이 사용자에게 불필요하다는 요구나 운영 증거가 확인되면 재검토
