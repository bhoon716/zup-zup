# 결정: 백엔드 정적 검사 도구는 PMD만 유지한다

- 상태: Accepted
- 결정일: 2026-10-12
- 범위: 백엔드 Java 정적 검사 도구와 검사 규칙의 재선정
- 대체 결정: 없음
- 관련 자료: [백엔드 재설계 체크리스트](../backend-redesign-checklist.md), [현재 Checkstyle 설정](../../apps/server/config/checkstyle/checkstyle.xml), [현재 PMD 설정](../../apps/server/config/pmd/pmd-ruleset.xml), [PMD 7.5.0 코드 스타일 규칙](https://docs.pmd-code.org/pmd-doc-7.5.0/pmd_rules_java_codestyle.html), [PMD 7.5.0 오류 검사 규칙](https://docs.pmd-code.org/pmd-doc-7.5.0/pmd_rules_java_errorprone.html)

## 문제와 확인된 사실

인지 부채와 근거 없는 기술 도입을 줄이기 위해 Checkstyle과 PMD를 함께 유지할 필요성을 검토했다. 현재 서버는 두 Gradle 플러그인과 각각의 설정 파일을 사용하며, 불필요한 import 검사 등 일부 역할이 겹친다.

PMD에는 불필요한 import, 제어문의 중괄호 사용, `sun.*` import 금지, 의도하지 않은 switch 분기 실행 등을 검사하는 규칙이 있다. 다만 지원되는 규칙 중 현재 프로젝트 설정에 활성화하지 않은 항목도 있다. 대응 규칙의 세부 판정과 예외 처리는 Checkstyle과 완전히 같지 않다.

현재 Checkstyle의 공백·중괄호 위치 같은 세부 형식 검사는 PMD의 기본 제공 규칙만으로 모두 동일하게 대체할 수 없다. IDE 포맷 사용과 CI에서 형식 위반을 검사·차단하는 것은 서로 다른 기능이다. 실제 버그 예방 효과나 유지 비용을 측정한 자료는 아직 없다.

## 선택지 비교

| 선택지 | 장점 | 비용·제약 |
| --- | --- | --- |
| 두 도구 유지, 중복·불필요한 규칙 정리 | 작성 규칙과 오류 검사 범위를 함께 확보 | 두 도구의 설정과 버전을 관리해야 함 |
| PMD만 유지, 필요한 규칙 재선정 | 잠재적 오류 검사에 집중하면서 도구 수를 줄임 | 기존 세부 형식 검사 일부가 사라짐 |
| Checkstyle만 유지 | 작성 규칙을 일관되게 적용 | PMD의 오류 검사 일부가 사라짐 |
| 두 도구 모두 제거 | 정적 검사 설정 관리 부담이 없어짐 | 해당 문제를 테스트·리뷰·IDE 등에서 발견해야 함 |

## 결정

1. 백엔드 정적 검사 도구는 PMD만 유지한다. Checkstyle 플러그인·실행 연결·설정은 제거 대상으로 삼는다.
2. 기존 PMD 규칙 전체를 그대로 유지한다고 확정하지 않는다. 재설계 코드에 필요한 검사부터 선정하고, 실제 오류 방지 효과·오탐·중복·불필요한 코드 수정 비용을 기준으로 규칙을 정리한다.
3. PMD에서 지원하는 규칙이라도 활성화되어야 검사된다는 점을 반영한다. Checkstyle 제거 전에 유지할 검사와 그 대응 규칙을 확인한다. 규칙 목록과 개별 설정값은 상세 설계에서 정한다.
4. 현재 Checkstyle이 수행하는 공백·중괄호 위치 등 세부 형식 검사를 CI에서 동일하게 강제하는 범위는 유지하지 않는다. IDE 포맷으로 보완할 수 있으나 그 자체가 CI 검사와 같은 보장을 제공한다고 간주하지 않는다.
5. 이번 결정만으로 새로운 포맷 도구나 사용자 정의 정적 검사 도구를 도입하지 않는다. PMD 위반의 CI 실패·배포 차단 연결 방식은 상세 설계에서 확인한다.

## 근거와 수용한 비용

사용자는 PMD만 남길 때 빠지는 검사와 PMD 규칙 추가로 유지할 수 있는 검사를 비교한 뒤 PMD만 유지하도록 선택했다. 두 도구의 관리 부담을 줄이고 필요한 오류 검사에 집중한다. 기존 형식 검사 일부가 사라지는 비용을 수용한다.

## 구현과 재검토

이번 변경은 의사결정 기록이다. Checkstyle 제거, PMD 규칙 변경, Gradle·CI·IDE 설정 변경이나 검사·테스트 실행은 하지 않았다.

형식 차이가 실제 유지보수 문제를 만들거나 PMD의 오탐·관리 비용이 효과보다 커지는 증거가 확인되면 검사 범위와 도구 구성을 다시 검토한다.
