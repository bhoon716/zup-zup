1. **데이터 보호부터:** 운영자 소유 환경에서 최근 DB dump·첨부 archive·off-host 사본과 checksum을 확인하고, 분리된 복구 환경에서 DB row와 파일 bytes를 함께 읽는 결과를 기록한다. 현 조사에는 이 증거가 없다.
2. **사용자 범위:** 기기별 MAU와 홈→검색→상세→구독·시간표·알림 흐름의 완료율, 관리자 작업 기기, 공개 검색 유입을 같은 기간으로 집계한다. 이를 바탕으로 모바일 전용·반응형 유지·관리자 분리의 비용과 손실을 비교한다.
3. **운영량:** 수집 실행시간/P95·좌석 변화율·DB write/binlog·검색 P95/query plan·outbox 첫 시도 지연·채널별 성공/실패/중복·host CPU/RSS/OOM을 같은 피크 기간에 측정한다. 단일 호스트·QueryDSL·polling·outbox·관측 stack의 적정성 판정에 사용한다.
4. **현 계약 확인:** OAuth/refresh/session·탈퇴 DB/Redis 실패·첨부 접근·lease 초과 fan-out·수동 SHA 재배포를 운영과 격리된 환경에서 재현한다. 과거 이슈의 통과 기록을 현 HEAD의 결과로 대체한다.
5. **대안 비교:** 각 후보에 동일한 입력 데이터·부하·사용자 과제를 주고 기능 성공률, 지연, 복구 시간, 비용, 유지 보수 변경량을 기록한다. 수치 목표와 유지/제거 결론은 운영자와 합의한 뒤 결정한다.
