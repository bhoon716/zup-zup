사용자 요청의 경로

HTTP 요청은 예약 scheduler와 별개의 서버 요청 기반에서 처리합니다. 서비스의 입력·소유권·권한 검사와 트랜잭션을 유지합니다.

로그인 · Redis 세션 · CSRF
1 · 외부 OAuth 유지Google 로그인 → Spring callback → 계정 확인. Discord 계정 연동 OAuth도 유지
2 · 세션 인증 보관AuthService가 기존 세션 ID를 교체하고 SessionPrincipal(userId, email)의 SecurityContext를 Redis 인덱스 세션에 저장
3 · 요청마다 현재 계정 검사SESSION 쿠키 → Redis 세션 → DB의 id·email·미탈퇴·현재 role 확인. 인증 요청은 Redis idle 30일만 갱신. 일반 응답은 SESSION 쿠키를 재발급하지 않음
4 · 변경 요청은 CSRFGET /api/auth/csrf → {token}. 웹은 X-CSRF-TOKEN 헤더를 전송하고 서버가 세션의 token과 검증

앱의 JWT·refresh 발급과 Bearer 인증·자동 재발급 경로는 제거했습니다. 401이면 로그인 필요 상태로 처리합니다. CSRF는 POST·PUT·PATCH·DELETE 등 변경 요청에 적용하며, 읽기 전용 POST /api/v1/courses/search만 예외입니다. GET·HEAD·OPTIONS는 기본 안전 메서드입니다.

로그아웃은 현재 기기 세션만 무효화합니다. 탈퇴는 email principal 인덱스에서 찾은 세션 중 userId까지 같은 계정의 세션 전체를 회수합니다. DB의 현재 id·email·탈퇴 여부가 맞지 않으면 세션을 무효화하고, role은 매 요청 현재 DB 값으로 갱신합니다.

새 namespace는 zup:sessions:v2입니다. 이 세션 전환을 배포하면 기존 인증 세션은 이어받지 않아 한 번 다시 로그인해야 합니다. Redis idle 30일은 활동 시 갱신됩니다. 후속 결정에 따라 쿠키는 브라우저 세션 쿠키이며 브라우저 재시작 후 로그인 유지는 보장하지 않습니다. Redis 회전·지연 저장 위험의 추가 조사는 사용자 지시로 생략했고 해결로 보고하지 않습니다. 세션 전환은 격리 Redis·HTTP와 브라우저 검증을 통과했습니다. 운영 배포를 수행한 기록은 아닙니다.

쿠키 Secure 표준은 운영에서 SERVER_SERVLET_SESSION_COOKIE_SECURE=true입니다. prod 프로필의 cookie.secure: true와 기본 Compose의 환경변수가 일치하며, 로컬 HTTP 개발용 Compose override만 false로 덮어씁니다. 로컬 override의 값을 운영 기준으로 사용하지 않습니다.

긴 수집의 공유 scheduler 점유

실제 scheduler·수집·outbox·신선도 메서드에 가짜 지연 fetch를 연결했습니다. 기존 로컬 clean 실행의 예: 수집 hold 305ms, 대기 outbox 305ms / 신선도 306ms 지연, 최대 동시 작업 1, 해제 후 각 2회 poll로 회복했습니다. 지연 측정은 hold 시작 뒤부터이며 축소 주기의 로컬 측정입니다. 운영 180초×4회 + 재시도 대기 18초 = 738초는 한 분류의 한 단계가 연속 timeout하는 조건부 계산이며 전체 수집 상한이나 실측이 아닙니다.
