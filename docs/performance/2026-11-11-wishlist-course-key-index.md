# 인기순 강의 검색의 찜 인덱스 검증

2026-11-11 · 로컬 격리 MySQL 8.4 · 기준 코드 `160537051`

## 요약

- 인기순 검색은 강의마다 `course_key`로 찜 수를 셈. `wishlists(course_key)` 인덱스 적용 후 학과 필터 검색 p95가 **539.46ms에서 45.64ms로 91.5% 감소**했음. 5개 비교 쌍 모두 빨라졌음.
- 필터 없는 검색은 인덱스 없이 5건 모두 12초 SQL 제한에 걸려 HTTP 500이었음. 인덱스 적용 후 5건 모두 HTTP 200으로 응답했고, 중앙값은 101.80ms였음.
- 쓰기 단독 시험에서 찜 등록 p95는 1.94ms 증가했고 삭제 p95는 0.70ms 감소했음. 두 조건 모두 회차별 변동이 컸으며, 인덱스가 쓰기 지연에 미친 영향은 분리해 확인할 수 없었음.
- 검색 개선을 근거로 `wishlists(course_key)` 인덱스 하나를 V33에 추가했음. [Flyway 마이그레이션](../../apps/server/src/main/resources/db/migration/V33__add_wishlist_course_key_index.sql)

## 측정 조건

- 강의 30,000개, 사용자 900명, 찜 8,997개를 같은 DB에 유지했음. 인기 강의 6개에는 각각 300~301개의 찜이 있었음. 초기 시험 데이터의 enum 값은 측정 전에 실제 저장 형식으로 정정했음.
- MacBook Air M1의 로컬 서버, MySQL 8.4에 2 vCPU와 2GiB, Redis 7.4, k6 1.3.0을 사용했음. 같은 서버에서 인덱스만 교체했음. MySQL 쿼리 제한은 12초, 검색 HTTP 타임아웃은 15초였음.
- 본 시험은 A(인덱스 없음)와 B(있음)를 다섯 번 교대했음. 각 조건에서 필터 검색 20건, 찜 등록·삭제 240쌍, 필터 없는 검색 1건을 순서대로 실행했음. 쓰기 단독 재시험은 5쌍을 추가하고 첫 실행 조건을 회차마다 번갈아 바꿨음.
- 필터 검색은 2026년 1학기 `학과 37`의 첫 두 페이지를 조회했음. 별도 집계 SQL로 계산한 페이지별 강의 키 30개의 순서와 다음 페이지 존재 여부를 모든 성공 응답에서 대조했음. 쓰기는 6개 계정이 각자 다른 강의를 등록·삭제했으며, 매번 응답의 찜 상태를 대조했음. 모든 회차 후 찜 테이블은 8,997건이었음.

## 지연 비교

단위는 ms임. min·max는 성공 요청 전체의 최솟값·최댓값임. p50·p95·p99는 회차별로 계산한 값 5개의 중앙값임.

| API | 인덱스 | 요청 | 오류 | min | p50 | p95 | p99 | max | p95 변화 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 학과 필터 검색 | 없음 | 100 | 0 | 336.71 | 368.12 | 539.46 | 540.83 | 656.25 |  |
| 학과 필터 검색 | 있음 | 100 | 0 | 28.39 | 33.12 | 45.64 | 45.67 | 197.08 | −493.82 |
| 찜 등록, 쓰기 단독 | 없음 | 1,200 | 0 | 14.83 | 28.61 | 46.71 | 62.47 | 966.72 |  |
| 찜 등록, 쓰기 단독 | 있음 | 1,200 | 0 | 14.20 | 24.18 | 48.65 | 72.98 | 1,044.89 | +1.94 |
| 찜 삭제, 쓰기 단독 | 없음 | 1,200 | 0 | 12.63 | 23.99 | 39.63 | 61.75 | 267.61 |  |
| 찜 삭제, 쓰기 단독 | 있음 | 1,200 | 0 | 9.03 | 21.37 | 38.94 | 49.28 | 1,100.09 | −0.70 |

- 필터 검색의 회차별 p95 범위는 372.02~598.29ms에서 40.31~169.52ms로 줄었음.
- 필터 없는 검색은 인덱스 없이 MySQL 오류 3024가 5회 발생했고, 실패 응답까지 12,018.31~12,796.81ms였음. 인덱스 적용 시 성공 응답은 90.49~116.93ms였음. 조건별 요청이 5건이므로 이 경로는 성공률과 범위로 비교했음.
- 첫 시험에서 쓰기 p95는 등록 33.05→30.38ms, 삭제 27.24→27.56ms였음. 인덱스 적용 첫 회차의 쓰기 꼬리 지연이 컸고, 쓰기 단독 재시험에서는 양쪽 조건 모두 큰 지연이 관측됐음. 등록 p95의 회차 범위는 21.84~95.77ms와 26.45~93.52ms였음. 삭제는 19.57~93.50ms와 25.94~200.97ms였음.

## 실행 계획과 적용

인기순 검색의 `COUNT(w1_0.id)` 상관 서브쿼리에서 `uk_wishlist_user_course` 전체 인덱스 스캔이 `idx_wishlist_course_key`의 `ref` 조회로 바뀌었음. MySQL 실행 계획의 찜 행 검사 추정치는 호출당 9,165개에서 1개였음. 바깥 강의 테이블의 전체 스캔과 정렬은 두 조건에 있었음. [인기순 쿼리](../../apps/server/src/main/java/bhoon/sugang_helper/planning/wishlist/repository/WishlistCourseSearch.java#L22)

추가 인덱스는 시험 데이터에서 16KiB InnoDB 페이지 23개를 사용했음. 약 368KiB임. 이 인덱스도 찜 등록·삭제 때 갱신됨. 운영 데이터의 지연과 인덱스 크기는 실제 데이터 분포와 부하에 따라 달라질 수 있음.

시험 데이터를 담은 V32 DB를 V33으로 올렸음. 찜 행의 해시와 PK·유니크·FK 메타데이터가 일치했고, `course_key` 전체를 키로 쓰는 비고유 인덱스 하나가 추가됐음. V33 JAR의 필터 없는 검색에서 HTTP 200과 예상 순서를 확인했음. 이 단건 확인은 위 비교 집계와 별개임. `./gradlew check migrationTest bootJar`가 통과했음. [스키마 검증 테스트](../../apps/server/src/test/java/bhoon/sugang_helper/common/config/FlywayMigrationValidationTest.java#L219)
