# 웹 화면의 반복 HTTP 요청

- 기준은 `b9fdec75a` 위 작업 트리에서 이번 웹 변경을 적용하기 직전 상태임.
- macOS arm64에서 Next.js 프로덕션 빌드와 Chromium으로 확인함. 같은 합성 공지·강의·시간표·사용자 데이터로 화면 동작을 재현함.
- 공지와 강의 상세는 별도 로컬 HTTP 서버에서 Next.js 서버와 브라우저가 보낸 GET을 합산함. 나머지 브라우저 경로는 Playwright가 받은 요청을 세고, 문의 상세 갱신은 실제 React Query에 연결한 API 호출을 셈. 각 숫자는 표에 적은 동작 한 번 기준임.

| 동작 | 세는 요청 | 변경 전 | 변경 후 |
| --- | --- | ---: | ---: |
| 공지 상세 첫 방문 | 같은 공지 상세 GET | 2 | 1 |
| 게스트 강의 상세 첫 방문 | 같은 강의 상세 GET | 2 | 1 |
| 게스트 강의 상세 첫 방문 | 내 별점 조회 | 1 | 0 |
| 검색 진입 후 추가 메뉴 1회, 공강 불러오기 메뉴 2회 열기 | 시간표 목록 | 3 | 1 |
| 검색 첫 화면에서 메뉴를 열기 전 | 시간표 목록 | 1 | 0 |
| 공개 검색에서 나갔다가 같은 조건으로 즉시 돌아오기 | 첫 페이지 검색 합계 | 2 | 1 |
| 시간표 첫 화면에서 찜 탭을 열기 전 | 찜 목록 | 1 | 0 |
| 설정 첫 진입 | 내 프로필 | 2 | 1 |
| 최신 관리자 DLQ 항목 선택 | 선택 항목 상세 | 1 | 0 |
| 문의 상태를 한 번 변경 | 열린 문의 상세 재조회 | 2 | 1 |

공지와 강의 공개 응답은 메타데이터와 같은 서버 요청에서 재사용함. 공지는 새 페이지 요청 시 공개 상태를 조회하고, 강의의 공개 데이터와 로그인 사용자 리뷰 상태는 별도 캐시로 관리함. SSR 데이터를 받지 못했거나 오래됐으면 브라우저가 다시 조회할 수 있음. 게스트는 공개 이모지 통계를 계속 조회함.

검색과 시간표에서 메뉴·탭이 열릴 때 목록을 요청하고, 공강 가져오기는 시간표 상세 캐시를 사용함. 로그인 전 초기 프로필 확인은 기존 세션 확인을 공유하며, 저장이나 연동 변경처럼 명시적으로 다시 읽어야 하는 흐름은 해당 갱신 경로를 사용함. DLQ는 최신 목록 데이터를 상세 초기값으로 사용하며, 오래된 목록에서는 상세를 서버에 조회함. 문의 상태·답변 변경은 목록과 영향을 받은 상세만 한 번에 무효화함.

이미 진행 중인 다음 페이지 요청은 다시 시작하지 않도록 했음. 공개 검색은 60초 동안 같은 검색 결과를 재사용하며, 찜 강의 검색은 계정별 캐시와 기존 즉시 만료 정책을 사용함. 취소와 일반 4xx는 자동 재시도하지 않고, 네트워크·서버 오류와 408·429의 기존 재시도 횟수를 유지함.

```sh
npm --prefix apps/web test -- --run
npm --prefix apps/web run e2e -- query-count.spec.ts --workers=2 --retries=0
```

측정은 통제된 로컬 요청 수 기준임. 메뉴나 탭을 처음 열 때는 해당 데이터를 읽어야 하며, 공개 상세의 로그인 사용자 리뷰 상태는 사용자 세션에서 확인함.
