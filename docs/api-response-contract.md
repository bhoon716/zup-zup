# 정상 응답 직접 반환 계약

정상 JSON API는 실제 기능 결과를 반환한다. 성공용 `code/message/data` 공통 래퍼와 프론트 `CommonResponse` 타입은 제거했다. 오류는 기존 `ErrorResponse`와 서버 안내 문구·오류 코드·상관 ID·`X-Error-Id`를 유지한다. 업무 데이터인 감사 `metadata.data`, Axios의 전송 응답 `data`, DELETE 요청 본문의 `data` 옵션은 다른 개념이다.

| 응답 종류 | 계약 |
| --- | --- |
| DTO·목록 | 객체·배열을 직접 반환한다. 필드명·검증·권한은 유지한다. |
| Page·Slice | `content`, `number`, `size`, `last`, 총개수 등 해당 페이지 객체의 메타데이터를 유지한다. |
| 피드백·답변 생성 | 기존 HTTP 201과 숫자 ID를 직접 반환한다. |
| 수동 수집 | 기존 문자열 payload를 JSON 문자열로 반환한다. |
| 인증 | GET /api/auth/csrf는 `{ "token": "..." }`와 Cache-Control: no-store, 로그아웃은 200/빈 본문이다. 자체 JWT 갱신 API는 제거했다. SESSION 쿠키와 X-CSRF-TOKEN 계약은 [세션 전환](redis-session-migration.md)을 따른다. |
| 데이터 없는 기존 200 성공 | 200과 빈 본문을 반환한다. 일괄 204로 바꾸지 않는다. |
| 대표 시간표 없음 | 기존 200을 유지하고 빈 본문을 반환한다. 웹 API 함수는 빈 문자열·JSON null을 null로 해석한다. |
| 기존 204 | 본문 없음과 상태를 유지한다. |
| OAuth 이동 | 기존 302·Location·쿠키를 유지한다. |
| 첨부 다운로드 | Resource/Blob·미디어 타입·Content-Disposition·소유권/관리자 확인을 유지한다. |
| Health | 준비 상태 200/503과 health DTO를 직접 반환한다. 503을 일반 업무 오류로 바꾸지 않는다. 내부 의존성·민감정보는 노출하지 않는다. |

프론트 API 함수는 Axios의 응답 객체에서 실제 payload를 꺼내 반환한다. 그 함수를 호출하는 훅·상태 저장소·화면은 공통 래퍼의 `.data`를 더 해제하지 않는다. Axios를 직접 쓰는 경로는 전송 응답의 `.data` 한 단계가 남는다. 성공 토스트는 기능별 문구 또는 실제 수집 결과 문자열을 사용하고 오류 문구는 기존 서버 오류 응답을 따른다. 정상 payload를 다시 감싸는 호환 interceptor는 추가하지 않았다.

서버 메타데이터·사이트맵의 fetch 경로도 직접 DTO·공지 Page의 content를 읽는다. 사이트맵은 기존처럼 첫 페이지를 사용하며 이번 변경에서 전체 페이지 수집 기능을 추가하지 않았다.

서버와 웹은 이 계약으로 함께 전환해야 한다. 아직 운영 배포하지 않았으며 옛 클라이언트의 성공 공통 래퍼 의존은 호환 대상으로 남기지 않는다. 실제 운영 모니터링 제공자의 설정은 접속하지 않았다. 저장소 health 문서는 새 status 경로로 갱신했다.

검증은 직접 배열·숫자·JSON 문자열·nullable·200 무본문·201·쿠키·공통 오류의 MockMvc 계약과 기존 페이지·파일·리다이렉트·인증/권한 검증을 포함한다. 웹은 nullable 대표 시간표와 서버 SEO·사이트맵 파싱을 보강하고 기존 리뷰 캐시 보존·세션 만료/CSRF·첨부 브라우저 흐름을 검증한다.
